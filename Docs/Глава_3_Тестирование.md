## Файл 4. `Docs/Diagrams/04_Sequence_Login.puml`

```powershell
@'
@startuml 04_Sequence_Login
title Последовательность «Вход пользователя в систему»

actor Пользователь as User
participant "Клиент WPF" as Client
participant "AuthController" as Ctrl
participant "AuthService" as Auth
participant "AppDbContext" as Db
participant "PasswordHasher" as Hasher
participant "TokenService" as Token
participant "AuditService" as Audit
database "PostgreSQL" as Pg

User -> Client : вводит логин и пароль
Client -> Ctrl : POST /api/auth/login { login, password }
Ctrl -> Auth : LoginAsync(request)
Auth -> Db : поиск User по Login
Db -> Pg : SELECT users WHERE Login = ...
Pg --> Db : строка или NULL
Db --> Auth : User или NULL

alt Пользователь не найден
  Auth --> Ctrl : UnauthorizedAccessException
  Ctrl --> Client : 401 "Неверный логин или пароль"
else Учётная запись заблокирована
  Auth --> Ctrl : UnauthorizedAccessException
  Ctrl --> Client : 401 "Заблокировано администратором"
else Учётная запись в LockoutUntil > now
  Auth --> Ctrl : InvalidOperationException
  Ctrl --> Client : 423 "Заблокировано до ..."
else Пароль неверный
  Auth -> Hasher : Verify(password, salt, hash)
  Hasher --> Auth : false
  Auth -> Db : FailedAttempts++ / при 3 — LockoutUntil = now+15min
  Db -> Pg : UPDATE users
  Auth -> Audit : LogAsync(userId, "LoginFailed")
  Auth --> Ctrl : UnauthorizedAccessException / 423
  Ctrl --> Client : 401 или 423
else Пароль верный
  Auth -> Hasher : Verify(password, salt, hash)
  Hasher --> Auth : true
  Auth -> Db : FailedAttempts = 0, LockoutUntil = NULL
  Db -> Pg : UPDATE users
  Auth -> Token : CreateSession(user)
  Token --> Auth : SessionInfo { Token, UserId, RoleName, ExpiresAt }
  Auth -> Audit : LogAsync(userId, "Login")
  Auth --> Ctrl : LoginResponse
  Ctrl --> Client : 200 { token, roleName, expiresAt, ... }
  Client --> User : открывает главное окно (MainShell)
end

@enduml
'@ | Set-Content -Path "Docs\Diagrams\04_Sequence_Login.puml" -Encoding UTF8
```

## Файл 5. `Docs/Diagrams/05_Sequence_SmetaCreate.puml`

```powershell
@'
@startuml 05_Sequence_SmetaCreate
title Последовательность «Создание и утверждение сметы»

actor "Главный экономист" as Econ
actor "Директор" as Dir
participant "Клиент WPF" as Client
participant "SmetaController" as Ctrl
participant "SmetaService" as Svc
participant "AppDbContext" as Db
participant "AuditService" as Audit
database "PostgreSQL" as Pg

== Создание сметы ==
Econ -> Client : нажимает «Создать смету» и заполняет форму
Client -> Ctrl : POST /api/smeta { projectId, formCode, year, items[] }
Ctrl -> Ctrl : проверка роли через [AuthorizeRole("Главный экономист")]
alt Нет роли
  Ctrl --> Client : 403 Forbidden
else Роль верна
  Ctrl -> Svc : CreateAsync(request, userId)
  Svc -> Db : проверка проекта и дубликата (ProjectId + FormCode + Year)
  Db -> Pg : SELECT smetas, projects
  alt Дубликат существует
    Svc --> Ctrl : InvalidOperationException
    Ctrl --> Client : 409 Conflict
  else Данные корректны
    Svc -> Db : INSERT smetas (Status="На утверждении") + INSERT expense_items[]
    Db -> Pg : INSERT ... RETURNING Id
    Svc -> Audit : LogAsync(userId, "Create", "Smeta", id)
    Svc --> Ctrl : SmetaDetailDto
    Ctrl --> Client : 201 Created
    Client --> Econ : смета в таблице со статусом «На утверждении»
  end
end

== Утверждение сметы ==
Dir -> Client : нажимает «Утвердить»
Client -> Ctrl : POST /api/smeta/{id}/approve
Ctrl -> Ctrl : проверка роли через [AuthorizeRole("Директор")]
Ctrl -> Svc : ApproveAsync(id, userId)
Svc -> Db : загрузка сметы со статьями
Db -> Pg : SELECT smetas, expense_items
alt Статус ≠ «На утверждении»
  Svc --> Ctrl : InvalidOperationException
  Ctrl --> Client : 409 Conflict
else Статус «На утверждении» и есть статьи
  Svc -> Db : Status = "Утверждена", ApprovedAt = now
  Db -> Pg : UPDATE smetas
  Svc -> Audit : LogAsync(userId, "Approve", "Smeta", id)
  Svc --> Ctrl : SmetaDetailDto
  Ctrl --> Client : 200 OK
  Client --> Dir : смета исчезла из «На утверждении»
end

@enduml
'@ | Set-Content -Path "Docs\Diagrams\05_Sequence_SmetaCreate.puml" -Encoding UTF8
```

## Как отрендерить `.puml` в `.png`

**Вариант А (рекомендую): VS Code.**
1. Установи расширение **«PlantUML»** (`jebbs.plantuml`).
2. Установи **Java** (JRE 8+) — https://adoptium.net.
3. Открой файл `.puml` → `Alt+D` (или правый клик → «Preview Current Diagram»).
4. Правый клик → **«Export Current Diagram»** → PNG → сохрани в `Docs/Diagrams/`.

**Вариант Б: онлайн.**
1. Открой https://www.plantuml.com/plantuml/uml/.
2. Вставь содержимое `.puml` в редактор.
3. Нажми **PNG** → сохрани картинку.

**Вариант В: CLI.**
```powershell
# скачай plantuml.jar с https://plantuml.com/download
java -jar plantuml.jar -tpng Docs\Diagrams\*.puml
```

## Глава 3. Тестирование и развёртывание программного средства

### 3.1. Методика тестирования

Тестирование программного средства проводилось на трёх уровнях, что соответствует современной практике верификации клиент-серверных приложений и требованиям руководства по проектированию программного обеспечения[1](https://learn.microsoft.com/dotnet/).

**Модульное тестирование** выполнялось с использованием библиотеки xUnit версии 2.6.2[2](https://xunit.net/). Тестированию подлежало математическое ядро программного средства, реализованное в классе `AnalysisService`, поскольку именно оно содержит расчётные алгоритмы, ошибки в которых приводят к неверным управленческим решениям. Всего разработано пятнадцать модульных тестов, покрывающих семь формул факторного анализа, а также граничные случаи: деление на ноль, отрицательные значения количества и стоимости, погрешность проверки суммы факторов.

**Функциональное тестирование серверной части** проводилось с использованием веб-интерфейса Swagger UI[3](https://swagger.io/) и командлета `Invoke-RestMethod` в среде PowerShell. Проверялись корректность HTTP-статусов, бизнес-правил (например, запрет редактирования утверждённой сметы), механизма авторизации по ролям и обработки исключительных ситуаций.

**Тестирование клиентского приложения** выполнялось вручную по сценариям, соответствующим каждой из пяти ролей. Проверялись корректность отображения данных, работа команд MVVM, обработка ошибочных ситуаций и переходы между экранами.

### 3.2. Модульное тестирование математического ядра

### 3.5. Развёртывание и инструкция по запуску

Программное средство развёртывается на рабочей станции под управлением операционной системы Windows 10 или Windows 11. Серверная часть может быть развёрнута на сервере под управлением Windows Server или Linux.

**Требования к среде:**
- .NET 8 SDK (для сборки) или .NET 8 Runtime (для запуска);
- PostgreSQL 18;
- Microsoft Visual Studio 2022 (для разработки) или любой редактор;
- Java Runtime (опционально, для рендеринга диаграмм PlantUML).

**Пошаговая инструкция по запуску:**

1. ☐ Установить .NET 8 SDK с официального сайта[4](https://dotnet.microsoft.com/download/dotnet/8.0).

2. ☐ Установить PostgreSQL 18 с официального сайта[5](https://www.postgresql.org/download/windows/). При установке задать пароль пользователя `postgres`, например `1234`, и порт `5432`.

3. ☐ Проверить, что служба PostgreSQL запущена:
   ```powershell
   Get-Service -Name "postgresql*"
   ```
   Статус должен быть `Running`.

4. ☐ Открыть файл `Server/appsettings.json` и указать строку подключения:
   ```json
   "DefaultConnection": "Host=localhost;Port=5432;Database=budget_institute;Username=postgres;Password=1234"
   ```
   Здесь `Password` — пароль, заданный при установке PostgreSQL.

5. ☐ Проверить, что пути к утилитам резервного копирования соответствуют установленной версии PostgreSQL:
   ```json
   "PgDumpPath":    "C:\\Program Files\\PostgreSQL\\18\\bin\\pg_dump.exe",
   "PgRestorePath": "C:\\Program Files\\PostgreSQL\\18\\bin\\pg_restore.exe"
   ```

6. ☐ Собрать решение:
   ```powershell
   dotnet build
   ```
   Ожидаемый результат: `Сборка успешно завершена. 0 Warning(s). 0 Error(s).`

7. ☐ Прогнать модульные тесты:
   ```powershell
   dotnet test
   ```
   Ожидаемый результат: `Пройдено 15, не пройдено 0`.

8. ☐ Применить миграции к базе данных (первый запуск):
   ```powershell
   dotnet ef database update --project Server --startup-project Server
   ```
   Миграция создаст базу `budget_institute`, все тринадцать таблиц, индексы и внешние ключи.

9. ☐ Запустить сервер:
   ```powershell
   dotnet run --project Server
   ```
   Ожидаемый результат в консоли: `Now listening on: http://0.0.0.0:5155`.

10. ☐ Запустить клиент (в отдельном окне терминала):
    ```powershell
    dotnet run --project Client
    ```

11. ☐ Войти в систему под одной из ролей:
    - Администратор: логин `admin`, пароль `Admin123!`;
    - Директор: логин `director`, пароль `Director123!`;
    - Главный экономист: логин `economist`, пароль `Economist123!`;
